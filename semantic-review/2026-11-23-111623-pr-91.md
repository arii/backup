# Text-light main screen and #81 spec drift cleanup (PR #91)

The PR removes the second skeleton and needle from "Not working?", flattens every `<details>` in `<main>`, hides the fix box while posture is good, drops the "Added: …" header note, and moves panel explanations into a "Good to know" list in Help. It also removes the unreachable `returning`/`seasoned` reveal jumps and `REVEAL_ADDED`, renames `STAGES.returning` to `STAGES.all`, and brings the onboarding and progressive-loading specs and the README in line with #81. `npm run check` passes locally (319 node tests, precache current). I could not run the Playwright e2e here (no Playwright or browser installed), so the e2e findings come from reading the diff.

Watch for: the "Not working?" panel can get stuck visible, because the "asked" reason is never cleared and the "practice" reason is cleared in only one place (confirmed). Several dropped copy lines were honesty or consent statements, not explanation (confirmed). The new e2e checks cover only two of the panel's visibility paths (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

"Not working?" visibility is now a reason set (`setupWhy`). Adding reasons works. Removing them does not: "start" is cleared only in `begin()`, "fixes" only when the diagnosis changes, "asked" never, and "practice" only by one button. The spec says the panel is hidden whenever tracking looks good and no reason holds, and the code does not guarantee that.

Hiding the fix box while GOOD matches the issue. The activity held label and the recovery bar still show because they only render outside GOOD, so no useful info is lost. The box is a `display:none` live region, so screen-reader announcements for it are lost too.

Removed elements have no dangling JS references, and the reveal rename has no missed usages. The README and spec edits match the code except for the stuck-panel rule and one hardcoded-number drift in Help.

Several shortened labels removed statements that were about consent or honesty (jaw check is not a measurement, shoulder reminders ask for OK first). Those should come back, in Help if not inline.

The e2e rewrites keep their intent except the hold-bar check, which now asserts the opposite and leaves the praise countdown untested. Two new word-count checks have thin headroom.

### setupWhy reason set: add paths are complete, clear paths are not

`setSetupReason` (`app.js:2318-2323`) shows the panel while any reason is set. The setters are "start" (`showSetupPanel`: failed start, `stopCamera`, no-WebGL at load, slow `load-hint`), "fixes" (`renderSetup`), "asked" (Help) and "practice" (practice finish).

```
start  : set by 2338, 2551, 2714, 3153   cleared by begin() 2567 only
fixes  : set/cleared by renderSetup 3168 (only when the diagnosis changes)
asked  : set by Help 3126                 never cleared
practice: set 3256                        cleared by "Try a breath check" 3269 only
```

"asked" is the clearest bug (confirmed). Picking Not working? in Help is meant to answer "show me what is wrong". With good tracking it shows "Tracking looks good" and the panel then stays, with the Learn the cues, intro and bug-report buttons, until reload. The new e2e asserts the panel is shown after the click and never that it can go away again. This contradicts the new Req 5a.1 text ("WHILE tracking looks good and none of these hold, THE panel SHALL be hidden"), since "asked" holds forever.

"practice" (confirmed): finishing practice shows the offer in this panel. If the user starts practice again, `startPractice` hides `#practice-breath` but the reason stays, so the panel lingers with nothing to offer. `stopCamera` calls `stopPractice` and then adds "start"; after a successful retry `begin()` clears only "start", so "practice" and "asked" survive a full restart. The practice-finish case also surfaces a panel in the top-right while the user is looking at the Learn the cues panel and the focus is on `#practice-next`, so the offer is easy to miss. It then persists until acted on.

"start" (likely): the `MutationObserver` on `#load-hint` calls `showSetupPanel` for any non-empty text and nothing removes the reason except `begin()`. Loading steps normally clear the hint before or at `begin`, so this is a narrow window.

No-WebGL (`applyWebGLState`, `2338`): at page load the panel shows before any start, with a status line "Start the camera or the demo and I will check your setup" and a *Learn the cues* button that answers "Start the webcam first". That matches the old behavior and the spec ("start step … failed"), but pre-start no-WebGL is not a slow or failed start. `begin()` then clears it even though the user is on the lower-accuracy MoveNet path; `lowpower-note` covers that.


### renderFix hides the box while GOOD

`renderFix` (`app.js:1828`) sets `cls = "quiet"` only in the plain GOOD branch, after the `heldLabel` branch, so an activity's held label (eye break, breathing, demo) still shows even if the underlying state is GOOD. The hold kinds `recover`, `confirm` and `slipping` all occur outside GOOD; only `praise` occurs in GOOD, and its text ("next looking good in …") is intentionally dropped per the issue. Title and text are rewritten every frame, so nothing stale is shown when the box reappears. Practice sets `fix active` directly at `3238` and the next normal frame resets it.

The angle tiles are now hidden except during practice (`body:not(.practicing)`), so during a real slouch the `.focus` highlight on the tile is invisible; the fix box text is the only pointer. This is expected from the issue. `.fix.ok` CSS (`index.html:107`, `110`) is now unused.

### Removed elements and the reveal rename

I found no remaining references in `docs/app`, `tests/` or `video/scripts` to `#today`, `#breaks-count`, `#coaching-note`, `#mode-note`, `setup-mini*`, `returning`/`seasoned`, `REVEAL_ADDED` or `shownStage`. `breaksTakenToday` is still used (`app.js:1021`). `setRevealAll` no longer toggles `details.open`, and no `details` remains in `<main>` except the welcome card's safety notice, which the e2e excludes. `ONBOARDING_VERSION` import removal is clean (fallow passes).

### Copy changes against the safety and claims rules

No line claims treatment or health benefit. The relax panel keeps a gentle-check line (`RELAX_SAFETY`). The breaks panel dropped "These are reminders to rest, not medical advice"; the removed line about leaving the camera is in Help. Issue 5 covers the jaw, shoulder-reminder and weekly-share labels. The README now says "What to fix appears only while you slouch", which is correct for the box. `SAFETY_SHORT` and `SAFETY_POINTS` are unchanged, so `ACK_VERSION` need not change; the `RELAX_SAFETY` shortening does not change meaning.

### e2e changes

The edited checks that opened `#setup-panel summary` now go through Help → Not working?, which is a fair route to the same controls. The "mini skeleton" check was replaced by hidden-while-good plus Help-shows-it, which loses nothing about the mini view since it was removed, but it also leaves no coverage of the panel's real purpose (fixes shown). `today` in the first-run check now reads `days` from `localStorage`, equivalent to the old text. The reminder-count and chime-only checks moved to Help text correctly.
